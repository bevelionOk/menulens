# What Breaks in Production — running register

Live list of the ways this system fails outside the demo, collected story by story from
the adversarial reviews and the design notes. Each entry names the trigger, what the user
sees, why it was accepted (or what the fix would be), and where it is documented. Feeds the
Epic-1 close ritual (DECISIONS.md), the RISKS register, and the walkthrough video's
"what breaks in production" segment (`[BREAKS]` highlights). Append-only.

| # | Trigger | What happens | Why accepted / first fix | Where |
|---|---|---|---|---|
| B1 | Two `POST /api/runs` within the same few ms (1.3) | Both pass the seriality check — two active runs | Check-then-insert is not atomic; the atomic guard (partial unique index on `processing`) turns a crashed run into a permanent lock (AD-10). Single operator + disabled submit makes it theoretical. Fix: advisory lock per POST. | D23; `spec-1-3` Design Notes |
| B2 | DNS rebinding on a URL run (1.4) | `dns.lookup` validates a public IP, Node's `fetch` resolves again and gets a private one — the guard is bypassed | AD-11 accepts the residual for a single trusted operator. Fix: pin the validated address with a custom undici dispatcher/`connect`. | AD-11; `spec-1-4` Design Notes |
| B3 | Menu host sits on CGNAT/NAT64/6to4 ranges (1.4) | `100.64/10`, `64:ff9b::/96`, `2002::/16` are not refused — reachable through the fetcher | Refusal list kept to AC1's enumerated ranges (anti-over-engineering); cloud-internal services on 100.64/10 would be exposed. Fix: one line each in `core/ssrf.ts`. | `spec-1-4` amendments (rejected findings) |
| B4 | JS-rendered menu page with a rich header/cookie banner (1.4) | Strips to ≥200 chars of nav/legal text → class `text`, model extracts zero or garbage dishes → `empty` or nonsense rows | Threshold is calibration data; `<head>`/nav are counted. Fix: exclude `<head>`/`<nav>`/`<footer>`, raise threshold after measuring dev menus. | `spec-1-4` (rejected findings) |
| B5 | Run acquired successfully while Postgres drops mid-pipeline (1.4/1.5) | Unexpected throw → `log.error`, run left `processing` → reads `interrupted`; Ana retries | Intended (AD-14): no `internal` failure reason; the staleness net is the catch-all. Cost: retry = new model call. | `spec-1-4` Boundaries |
| B6 | Transient 429/5xx from OpenAI (1.5) | `failed(model_error)` immediately — no retry (`maxRetries: 0`) | FR6 "one retry, one timeout" is kept literal; a rate-limit burst fails runs Ana must retry by hand. Fix: retry once on 429 with `Retry-After` if ever multi-operator. | `spec-1-5` Design Notes |
| B7 | Model output truncated at its default output cap on a very long menu (1.5) | `incomplete` (`max_output_tokens`) → invalid output → the one retry re-sends the same input → fails identically → `failed(model_invalid_output)`, double cost | No `max_output_tokens` set (Ask-First param); the retry is deterministic waste on this path. Fix: set a generous cap and skip the retry on `max_output_tokens`. | `spec-1-5` amendments (rejected) |
| B8 | Attempt 1 throws inside the SDK's `parse` (malformed JSON) (1.5) | Tokens were billed but `usage` is never returned — the run's measured cost under-counts | No hand-parsing allowed (AD-12); only the rare malformed-JSON path loses the number. | `spec-1-5` amendments |
| B9 | Two slow-but-valid model attempts (1.5) | Stage `extracting` can run up to 2× `MODEL_TIMEOUT_MS`; the anchor re-bump keeps it from reading `interrupted`, but Ana waits up to ~4 min | Accepted: the retry is a real event. Fix: cross-attempt deadline. | `spec-1-5` Boundaries |
| B10 | Scanned/visual sources (1.5/1.6) | Evidence quotes cannot be machine-verified (no ground text) — a wrong `declared` passes T6 and reaches Ana as "declared" | By design (FR19): Ana verifies visually in the evidence panel. The gate is only as honest as her review on visual runs. | PRD FR19; AD-6 |
| B11 | Provider API shape drift (1.5) | `responses.parse`/`zodTextFormat`/error classes are verified against `openai@7.5.0` only; a caret upgrade can change `system` vs `developer` role handling or the refusal shape | Majors scaffold-pinned (R-13); the seam isolates the blast radius to one file. | RISKS R-13; `spec-1-5` Code Map |
| B12 | Seam mocked above the adapter in the single test (1.5/1.8) | Retry/mapping/usage semantics of the real adapter never run in CI | Deferred to 1.8 (stub-client sub-assertion or a DECISIONS record). | `deferred-work.md` |
| B13 | Source text carries a soft hyphen, ZWSP or BOM (1.6) | The pinned chain keeps them, the model's quote does not — T6 downgrades a correct `declared` allergen and T4 fires on a correct name; `html-to-text` itself decodes `&shy;` into the ground text | Chain is frozen (AD-7/D20) and widening it is Ask-First. Fix: drop default-ignorable code points inside the one chain. | `deferred-work.md`; `spec-1-6` amendments |
| B14 | `price_raw` is `"1.250 €"` or `"12,345 €"` (1.6) | A single separator is always read as a decimal: `1.25` / `12.35` persisted, and the row can still be `reliable` — a wrong price marked auto-checked | Thousands heuristics are Ask-First (spec Boundaries); refusing (T2) on a three-digit group or >2 decimals is the honest fix, pending Pablo's call. | `deferred-work.md`; `spec-1-6` amendments |
| B15 | Variant names the source prints differently (1.6) | T4 fires on rows that are correct — the live fixture run flags 4 of 11 rows (`Paella de marisco (media ración)`) purely because punctuation is not normalized | By design (D20): one chain, no second normalization; an honest "not traceable" beats a silent match. Calibrate on real menus before widening. | `spec-1-6` Design Notes |
| B16 | The `saving` transaction rolls back (1.6) | `finishRun` already logged `run finished status=done` inside the transaction — the operational record claims a terminal state the database never reached | Deferred: the terminal line should be emitted after commit. NFR5 makes the log the record, so this is an honesty defect, not just noise. | `deferred-work.md` |
| B17 | A run leaves `processing` between `validating` and `saving` (1.6) | `setTerminal`'s guarded UPDATE matches zero rows but reports nothing, so the transaction commits the dish rows onto a non-`processing` run with no status change | No second writer exists today (staleness is derived, never written — AD-14), so this cannot fire yet. Fix: return the rowcount and throw inside the transaction. | `deferred-work.md` |
| B18 | The same evidence phrase appears twice in the menu (1.6) | `indexOf` returns the first occurrence, so the persisted offsets — and the 2.4 evidence panel — may highlight another dish's line | Accepted: the flag and provenance stay honest; the highlight is an aid. Fix: prefer the occurrence nearest the dish's own name offset. | `spec-1-6` amendments (deferred) |
| B19 | The submit page is polled after months of use (M1) | `GET /api/runs` has no `LIMIT` and its dish aggregate groups the whole `dishes` table — every run ever, on every poll; the recent-runs list and the payload grow without bound | Pagination is Ask-First in the M1 spec and a single operator's run count grows slowly. Fix: `LIMIT 50` on the run query and scope the aggregate to those ids. | `spec-1-7` Boundaries |
| B20 | A run's `saving` transaction commits between the list's two queries (M1) | `listRunsWithCounts()` reads runs, then the aggregate — a run read as `processing` can carry the dish count committed a millisecond later, so one poll renders "still running, 0 of 11 resolved" | Cosmetic and self-correcting on the next poll; the reverse skew (`done` with 0 dishes) is impossible because dishes and `done` commit together (AD-5). Fix: wrap both reads in one repeatable-read transaction. | `spec-1-7` Code Map |
| B21 | Retry on a run whose source was an upload (M1) | The failed/interrupted/empty screen offers "re-upload the file" instead of a retry button — the bytes are in `source_artifacts` but no route replays them, so Ana has to find the original file again | Deliberate: the M1 spec caps the API at four routes, and a button that cannot work is worse than an honest instruction. Fix: `POST /api/runs/:id/retry` reusing the stored artifact. | `spec-1-7` Design Notes |
| B22 | The browser clock disagrees with the server's (M1) | The elapsed timer is `Date.now() - created_at`, so a skewed client clock shows a wrong — possibly negative, clamped to 0 — elapsed on the waiting screen, exactly where the product promises a *measured* number | Accepted for a single local operator; the alternative is a server-supplied `now` on every poll. Fix: derive elapsed from a server timestamp echoed in the run payload. | `spec-1-7` Boundaries (FR5) |
| B23 | The server tightens or loosens its URL rules (M1) | `validateUrl` in `web/src/routes/submit.tsx` re-implements the four checks `POST /api/runs` applies; if either side changes, the UI either blocks a URL the server accepts or lets through one it rejects | Accepted: the server still decides — the client copy is a latency saver, not a gate, and a drift shows up as the server's own envelope. Fix: move the rule into `shared` so both read one schema. | `spec-1-7` I/O matrix (E1) |
